# نداء — طلب ودفع ذاتي، مؤقت الطلب، ولاء في المحفظة، SMS، وربط POS

## ماذا يوجد في المشروع
| الملف | وظيفته |
|---|---|
| `public/index.html` | الواجهة كاملة: شاشة العميل `/#customer`، شاشة الكاشير `/#cashier`، الإعدادات `/#admin`. عربي/إنجليزي، فاتح/داكن. |
| `server.js` | الخادم وكل نقاط الـ API |
| `lib/core.js` | منطق الطلبات: رقم الطلب عند الدفع، المؤقت، الأختام، نصوص الرسائل |
| `lib/menu.json` | المنيو (الاسم، السعر، **وقت التحضير بالدقائق** لكل صنف) |
| `adapters/pos.js` | الجسر مع نظام الكاشير |
| `adapters/sms.js` | Twilio أو Unifonic أو أي مزود محلي |
| `adapters/payments.js` | Stripe أو دفع تجريبي، وقالب لأي بوابة محلية |
| `adapters/googleWallet.js` / `appleWallet.js` | إصدار بطاقة الولاء وتحديث الأختام تلقائياً |

## التشغيل
1. ثبّت Node.js 18 أو أحدث.
2. `npm install`
3. انسخ `.env.example` إلى `.env` وعبّئ القيم.
4. `npm start` ثم افتح `http://localhost:3000/#customer`
5. ارفعه على خادم بـ HTTPS (Render أو Railway أو VPS مع Nginx). **HTTPS إلزامي** للدفع والمحفظة.

بدون أي إعدادات يعمل كل شيء بوضع تجريبي: الرسائل تُطبع في الطرفية، والدفع صفحة تجريبية.

## رموز QR
اطبع QR يفتح: `https://your-domain.com/#customer`
ويمكنك عمل QR لكل طاولة أو لموقف السيارات بنفس الرابط.

## كيف يعمل المؤقت
وقت الانتظار = أطول وقت تحضير في الطلب + (عدد الطلبات قيد التحضير × «دقائق لكل طلب في الطابور»).
الكاشير يضيف 2 أو 5 أو 10 دقائق بزر واحد، فيتحدّث المؤقت عند العميل فوراً، وتصله رسالة إذا كانت الإضافة 5 دقائق أو أكثر.

## الدفع اليدوي
إذا اختار العميل «ادفع عند الكاشير» يظهر له رمز من 4 أحرف. الكاشير يضغط «تأكيد الدفع» فيُولَّد رقم الطلب ويبدأ المؤقت وتصل الرسالة.

## ربط نظام الكاشير (POS)
لا يوجد معيار موحد بين أنظمة POS، لذلك الربط من اتجاهين في `adapters/pos.js`:
- **نداء ← POS**: عند الدفع الإلكتروني يُرسل الطلب إلى `POS_PUSH_URL` ليُسجَّل في المبيعات.
- **POS ← نداء**: إذا دُفع طلب على جهاز الكاشير، يرسله POS إلى `POST /api/pos/webhook` مع الهيدر `x-pos-secret`، فيُرجع له رقم الطلب لطباعته على الفاتورة، ويُضاف ختم وتصل رسالة.

مثال لما يرسله POS:
```json
{ "items": [{ "sku": "lat", "qty": 2 }], "phone": "0791234567", "lang": "ar", "paid": true }
```
اجعل `sku` في POS مطابقاً لـ `id` في `lib/menu.json`. إذا كان نظامك لا يدعم Webhooks، اطلب من مزوده مفتاح API واكتب دالة سحب دورية بنفس الشكل.

## Google Wallet
1. أنشئ حساباً في Google Pay & Wallet Console واحصل على **Issuer ID**.
2. في Google Cloud: فعّل Google Wallet API، أنشئ Service Account، نزّل ملف JSON إلى `certs/`، وأضف بريد الحساب كمستخدم في Wallet Console.
3. عبّئ `GOOGLE_ISSUER_ID` و`GOOGLE_SA_JSON` و`LOGO_URL`.
4. الأختام تتحدث على جوال العميل تلقائياً بعد كل طلب.

## Apple Wallet
1. حساب Apple Developer (مدفوع) ← Identifiers ← **Pass Type ID**.
2. أنشئ شهادة Pass Type ID، وحوّلها إلى `signerCert.pem` و`signerKey.pem`، ونزّل شهادة **WWDR G4** وحوّلها إلى `wwdr.pem`، وضعها في `certs/`.
3. أضف صور `icon.png` و`icon@2x.png` و`logo.png` داخل `models/loyalty.pass/`.
4. عبّئ متغيرات `APPLE_*`. البطاقة تتحدث تلقائياً عبر APNs بعد كل ختم.

> ملاحظة مهمة: Apple وGoogle لا تسمحان بإضافة بطاقة إلى المحفظة بدون ضغطة من العميل. النظام يعرض الزر المناسب تلقائياً (Apple على iPhone وGoogle على أندرويد)، والعميل يضغط مرة واحدة فقط، وبعدها تتحدث الأختام وحدها.

## SMS
- `SMS_PROVIDER=twilio` أو `unifonic` أو `http` لأي مزود محلي.
- سجّل اسم المرسل (Sender ID) لدى المزود، فبعض الدول تشترط ذلك قبل الإرسال.
- الرسائل: تأكيد الطلب مع الوقت والأختام ورابط المتابعة، تأخير الطلب، الطلب جاهز، مشروب مجاني.

## تقييم Google
ضع رابط «اطلب تقييمات» من Google Business Profile في الإعدادات. الزر يظهر لكل العملاء بعد الاستلام، والملاحظة الخاصة اختيارية بجانبه. لا يوجد فلترة للتقييمات السلبية لأن Google تمنع ذلك.

## قبل الإطلاق
- غيّر `CASHIER_PIN`.
- انقل التخزين من `data/db.json` إلى PostgreSQL إذا عندك أكثر من فرع.
- جرّب الدفع ورسائل SMS والمحفظتين ببيانات حقيقية؛ الكود مكتوب حسب وثائق كل مزود لكنه يحتاج اختباراً بحساباتك.
- أضف سياسة خصوصية لأنك تجمع أرقام الجوالات.
